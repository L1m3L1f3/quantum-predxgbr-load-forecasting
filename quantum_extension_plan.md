# Quantum Extension Plan

## Classical Baseline

The classical baseline is the root-level XGBoost pipeline in `baseline_pipeline.py`, run by:

```bash
.venv/bin/python run_all.py
```

The verified default experiment uses `PJME_hourly.csv` and causal historical load features to avoid target leakage. This XGBoost result should be treated as the reference baseline for future hybrid quantum machine learning experiments.

## Dataset to Reuse

Use the same PJME hourly dataset:

- File: `data/PJME_hourly.csv`
- Datetime column: `Datetime`
- Target column: `PJME_MW`
- Units: MW
- Split date: `2015-01-02`

For fair comparison, quantum models should use the same train/test timestamps as `results/run_config.json`.

## Features to Reuse

Start with the same engineered feature table generated by the classical runner:

- `processed/pjme_train_features.csv`
- `processed/pjme_test_features.csv`

The full feature set has calendar features, lag features, and rolling statistics. A quantum neural network may need fewer input dimensions because current quantum simulators and hardware have limited qubit counts. If dimensionality reduction is needed, apply it only after the train/test split and fit scalers or PCA on the training set only.

## Metrics to Reuse

Use exactly the same metrics:

- MAE
- RMSE
- MAPE
- R2
- Training time

Save quantum results separately, for example:

- `results/quantum_metrics.csv`
- `results/quantum_predictions.csv`
- `results/quantum_training_history.csv`

## Fair Hybrid Quantum Comparison

A fair hybrid quantum neural network comparison should:

1. Use the same dataset file and train/test split.
2. Use the same forecasting horizon.
3. Avoid target leakage in the same way as the classical `--feature-mode causal` pipeline.
4. Fit any scalers, encoders, or dimensionality reduction only on training data.
5. Report the same metrics on the same test timestamps.
6. Save predictions so errors can be compared timestamp by timestamp.
7. Compare model complexity and training time, not only prediction accuracy.

## Implemented Starter Baseline

A first runnable GPU-backed hybrid quantum feature baseline now exists:

```bash
.venv/bin/python run_quantum.py --device lightning.gpu --n-qubits 4 --n-layers 2 --max-train-samples 1000 --max-test-samples 500
```

This is a starter comparison model, not a tuned quantum neural network. It uses PennyLane `lightning.gpu`, PCA to map the classical feature space into qubit angles, a fixed entangling quantum circuit, and a ridge regression readout.

Two additional fair search paths were added:

```bash
.venv/bin/python run_hybrid_quantum_residual.py --device lightning.gpu
.venv/bin/python run_quantum_augmented_xgboost.py --device lightning.gpu
.venv/bin/python run_quantum_matched_sweep.py --device lightning.gpu
```

Current finding: the tested fixed quantum feature maps do not beat the XGBoost baseline. The residual experiment selected `residual_alpha = 0.0`, meaning held-out training data rejected the quantum correction. The quantum-augmented sampled XGBoost run also underperformed the baseline on the same sampled rows. This is useful negative evidence: the working GPU quantum infrastructure is ready, but the present random feature circuits are not enough to outperform a strong tree baseline.

The matched low-data sweep gives a defensible narrower win: when both sides use the same PCA-reduced inputs, same sampled rows, and small readout models, `hybrid_pca_quantum_*` beats the best matched PCA-only classical model in several settings. A verified quick sweep used:

```bash
.venv/bin/python run_quantum_matched_sweep.py --device lightning.gpu --train-samples 128 --test-samples 128 --qubits 2 3 4 --layers 1 2 --seeds 1 2 3
```

Best example from `results/quantum_matched_sweep/quantum_matched_sweep_winners.csv`:

- `seed=1`, `n_qubits=3`, `n_layers=1`
- Best matched classical: `classical_pca_xgboost`, MAE `2589.21`
- Best hybrid quantum: `hybrid_pca_quantum_xgboost`, MAE `2504.92`
- Improvement: `84.29` MAE

This should be presented as a low-data matched-comparator result, not as a claim that quantum beats the full XGBoost baseline.

## How to Pursue a Real Win

Avoid claiming a win by changing the test split, using test labels for tuning, or enabling target leakage. The original paper-style rolling features can make results look better because they include the current target in rolling statistics; that is not a fair quantum/classical comparison.

More defensible next attempts:

1. Train the quantum circuit parameters instead of using random fixed circuits.
2. Use a low-data regime comparison, where both classical and quantum models are trained on the same small training set.
3. Compare against a matched-size classical neural network, not only against full-strength XGBoost.
4. Add exogenous features such as temperature/calendar/holiday data if available, then compare all models on the expanded dataset.
5. Cache full quantum features and run a proper validation sweep over qubits, layers, encodings, readouts, and seeds.
